# 食光

首期提供饮食偏好、忌口与每餐准备时间输入，生成早餐、午餐、晚餐的搭配、简短准备方式和替换选项。使用平台的卡片、表单、按钮与主题 token，支持亮暗主题和移动端单栏布局。

## 使用方式

1. 填写口味或食材偏好，可补充忌口、过敏食材并选择准备时间；“填入示例”只填表，不发送请求。
2. 点击“生成今日食谱”，首次使用由宿主请求 AI 授权。
3. 查看三餐建议；修改偏好后重新生成。生成中禁止重复提交；拒绝授权、网络失败或回复不完整时显示错误，可重试。

重新生成失败会保留上次成功结果；修改输入后会提示结果仍基于旧偏好。AI 输出作为纯文本显示，不执行 HTML。响应需包含完整三餐及替换建议，否则提示重试，不展示残缺计划。

## 数据与 AI 边界

- 仅声明 `ai.invoke`，通过 `context.invokeAI` 使用平台网关与授权机制。
- 发送本页填写的偏好、忌口、准备时间，以及固定的食谱生成指令；不读取用户资料、其他插件数据或足迹。
- 不持久化、不发布足迹。输入与结果仅在当前组件内存保留，离开或刷新后清空。平台独立保存的 AI 授权可在插件中心撤销。
- 用户离开时由宿主释放 context 并尝试中止请求；这不能撤回服务商已收到的数据。
- 偏好上限 1500 字、忌口上限 500 字；提示要求 AI 遵守饮食限制，但不能保证建议完全准确，食用前仍需核对配料及过敏原。
- 仅提供日常饮食参考，不做医疗诊断、营养处方或寿命预测。首期不包含图片识别、餐厅推荐、热量目标或跨设备同步。

## 验证

```sh
npm test -- plugins/meal
npm run typecheck
npm run build
```

手工验收：在插件中心启用食光，检查空输入禁用、示例填入、授权同意/拒绝、成功三餐、失败重试与旧结果保留；检查键盘操作、窄屏和亮暗主题。真实 AI 调用需要平台配置可用的服务商凭证。
