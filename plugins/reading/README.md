# 知行 · reading

首期提供阅读评价输入和 AI 阅读辅助。输入书名或文章名，可选填阅读目标、个人评价及原文摘录，分析阅读价值、适合读者和全文／逐章／逐节阅读与 AI 总结的取舍。章节解析和阅读清单不在首期范围。

## 使用与数据边界

- 仅声明 `ai.invoke`，经 `context.invokeAI` 使用平台网关及授权流程，不直接访问模型或 API key。
- 点击“分析阅读价值”或“重试分析”会发送当前四项输入；发送前页面明确提示，首次调用需宿主授权。不读取其他插件、个人资料或足迹，不发布事件。
- 无原文时，提示词与结果界面都说明不确定性；有摘录时只将其视为局部资料。禁止虚构目录、章节、引用和作者观点。AI 输出以纯文本渲染，不执行 HTML。
- 输入上限分别为 160、400、600、2400 字符；加上提示词后，单条消息仍在网关 5000 字符限制内。
- “保存本机草稿”显式保存一份输入到插件隔离的 `draft` 键，格式 `{ version: 1, title, goal, review, excerpt }`。不自动保存，AI 结果不持久化，不同步设备。
- “清空输入与本机草稿”删除草稿并清空当前页面；失败时保留内容。平台清理插件数据也可删除草稿。删除本地数据不能撤回 AI 服务已经接收的内容。
- 存储异常、无效数据、AI 失败及空响应均有提示和重试路径。分析期间锁定输入，避免结果与输入错配；卸载后忽略异步回调。

## 视觉与验证

复用平台 `card`、`field`、`btn`、`notice` 和主题 token，局部样式以 `reading-` 为前缀。沿用 fire 的眉题、双栏布局和柔和卡片，760px 以下单栏，兼容深色主题、键盘操作及状态播报，无新增动画。

运行 `npm test -- plugins/reading` 验证输入、存储、AI 边界及视图交互；运行 `npm run typecheck` 和 `npm run build` 验证平台集成。
